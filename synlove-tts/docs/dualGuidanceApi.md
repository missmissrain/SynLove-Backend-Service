# Breeze TTS 独立双引导接口

服务：家庭服务器回环端口 `7862`，沿用既有鉴权。
合成入口：`POST /v1/audio/speech`，同步返回 WAV。

## 请求字段

```json
{
  "input": "待合成的台词。",
  "instruction": "虚弱、垂暮、恐惧、强装镇定、绝望、濒临崩溃、保持理智。",
  "refAudioBase64": "<参考WAV的Base64内容>",
  "refText": "<参考WAV准确对应的文字>",
  "cfgScaleRef": 0.3,
  "cfgScaleIns": 4.0,
  "seed": 19170902,
  "maxChars": 500,
  "response_format": "wav"
}
```

- `cfgScaleRef`：参考音频分支的引导系数。
- `cfgScaleIns`：情绪、音色等文字提示分支的引导系数。
- 两个独立系数必须同时提供，且为非负有限数值；`0` 是有效值。
- 双引导要求同时提供参考音频、参考文本、文字提示。
- 两个系数不是百分比，不要求相加为 1；参考音频可能同时携带音色、语速、口音和表演习惯。
- 提供独立系数时，原 `cfgScale` 不参与双引导计算。
- 不提供两个独立系数时，保留既有流式运行时及 `cfgScale` 行为。

## 推理实现

双引导复用已加载的同一份 INT8 权重和外部声码器，调用模型已有的原生生成实现。模型前向继续使用既有 GPU/CPU 布局。没有复制环境或下载新权重。

每步对三个分支计算：

```text
结果 = 无条件分支
     + cfgScaleRef ×（参考音频分支 - 无条件分支）
     + cfgScaleIns ×（文字提示分支 - 无条件分支）
```

此处“无条件”仍然包含待合成文本，只是不带参考音频和文字提示。

原生双引导没有使用快速流式路径的 CUDA Graph 优化；其延迟与原接口可能不同。

原生生成的标准重复惩罚器会把初始文字 token 当成音频词表索引，造成越界。本封装将标准重复惩罚设为 `1.0`，通过 `BreezeAudioRepetition` 单独对已生成音频的第一码本应用既有 `1.1` 惩罚。没有修改全局 PyTorch 排序或抽样方法。

码本输出头与既有快速路径统一使用 FP32；原生路径调用输出头时通过局部输入钩子对齐其输入精度，结束后移除钩子。其余模型权重布局不变。

## 当前试听状态

首轮 `cfgScaleRef=0.3, cfgScaleIns=4.0` 的13.76秒样本被用户明确判定为“声音失真很严重”，不得作为通过的推荐参数。该样本未出现导出WAV满幅削波，但不能据此排除模型内部失真。

首轮两组双引导样本在输出头精度对齐修正之前生成。后续短试音使用 `cfgScaleRef=0.3, cfgScaleIns=1.5` 并启用精度修正；该比较同时改变两个因素，不能据此单独归因于权重或精度。

## 运行证据

- `GET /health` 新增 `dualGuidanceVersion: 1` 与参数列表。
- 每次双引导生成在服务器原输出目录下的 `guidanceAudit/` 保存请求 ID、实际系数、分支形状、实际模型嵌入入口及完成状态。
- 原服务修改前的原始字节另行备份；部署脚本位于本机 `TempleAudioDrama/prologueProduction/TtsDualDeployment.py`。
- 音频成功生成只能证明接口和推理路径可运行，人物情绪与声线是否合格仍需试听。
